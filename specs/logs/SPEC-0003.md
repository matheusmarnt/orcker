## S2 — plan

First new crate of the fork: a 100% pure library turning a typed stack model
into a rendered `docker-compose.yml` string for the PostgreSQL reference
topology (PRD D02, FR-022 partial).

Design decisions taken before writing code:

1. **No `orcker-core` dependency.** `orcker_core::PhpVersion` is a
   `(major, minor)` struct accepting `major ∈ 5..=9`, and core's site-name
   validator is private (only `normalize_site_name` / `slugify_site_name` are
   public). R5 needs PHP pinned to `8.1..=8.5` and a `SiteName` newtype;
   widening core's public API would put the diff outside this spec's surface.
   `orcker-stack` therefore defines its own value types, styled on
   `crates/orcker-core/src/tld.rs` (validated newtype + `FromStr` + `Display` +
   typed reason enum). `thiserror` is the only dependency.
2. **Hand-rolled YAML emission**, as the spec mandates (`serde_yaml`-style
   crates are not approved). Determinism comes from construction: one ordered
   string builder, no maps, so R4 holds by design rather than by sorting.
3. **`Ports` is a pair type.** The failure that matters — two services fighting
   over one loopback port — is a property of the pair, not of either value, so
   validation lives there. It also keeps `StackConfig::new` at seven arguments,
   under clippy pedantic's `too_many_arguments` threshold.
4. **Acceptance tests are integration tests.** The checklist names
   `orcker_stack::compose::*` and `orcker_stack::validate::*`, which is the path
   cargo prints for `tests/compose.rs` / `tests/validate.rs`. A `#[cfg(test)]
   mod tests` inside `src/compose.rs` would print `compose::tests::*` and miss
   the contract.

One lint fix during the gate: `clippy::doc_markdown` rejected the bare word

## S5 — evidence

### AC5 — `docker compose config`

The fixture is byte-identical to the render (pinned by AC1), so the check ran
against it in a scratch directory with a synthetic `.env`:

```
$ docker compose -f docker-compose.yml config
exit=0
--- stderr ---
(empty)
```

Exit 0 with **no warnings**, satisfying FR-022 AC2. Resolved output confirms the
contract: `host_ip: 127.0.0.1` on both published ports, `restart: 'no'` on all
three services, `condition: service_healthy` on `app`'s dependency,
`read_only: true` on the nginx storage bind, `development` resolved as
`external: true`.

### The `$$` escape, verified rather than assumed

The healthcheck reads `pg_isready -U $${DB_USERNAME} -d $${DB_DATABASE}`. Compose
prints it back as `$$...` in `config` output, which looks like the escape did not
take. Checked with a two-service probe instead of guessing:

```
services:
  a: command: ["sh","-c","echo $${FOO}"]   # config -> echo $${FOO}
  b: command: ["sh","-c","echo ${FOO}"]    # config -> echo hostvalue   (.env FOO=hostvalue)
```

`$$` blocks host-side interpolation and `config` re-escapes the literal `$` so
its output stays a valid compose file; the container shell expands it from
`env_file` at runtime. A single `$` would have been substituted on the host to an
empty string, and warned. The escape is correct.
