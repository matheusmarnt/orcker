## S2 — plan

Approved plan: extract the scanner into `tests/deadExports.mjs` shared by the
existing delta script and a new standing test; fix the three blind spots there;
add a shrink-only allowlist (`tests/dead-export-allowlist.txt`) plus a
dynamically-computed contract-mirror exemption for `ipc/types.ts`
(`tests/contractMirror.mjs`, R3) so the exemption expires by itself instead of
going stale like a static line would; dispose of the inherited dead set; extend
to the fixed point.

Two Explore agents built the disposition data before the plan was finalised:
one mapped all 41 `ipc/types.ts` dead names against `crates/orcker-ipc/src` (26
with a live Rust counterpart, 15 without), the other classified the 36
non-`ipc/types.ts` dead names by same-file and test-only usage (29
UNEXPORT-eligible, 6 DELETE, 0 test-only at that snapshot - the R2 fix in S4
below made the 29 moot, since a genuinely same-file-used export is no longer
reported dead at all).

## S4 — implement

Fixed `deadExports.mjs` (comment/string stripping before matching, test files
excluded from both passes, home-file usage counted past the declaration line)
and `contractMirror.mjs` (`match[2]`); reran both unit suites green.

**Fixing R2 collapsed far more of the inherited 77 than expected**: many
`ipc/types.ts` interfaces cross-reference each other in the same file (a
`Response` variant's payload embedding another named interface), which the old
scan's `path !== home` rule could never see. Absolute count after the fix: 31,
not 77. `dead-export-delta.mjs` (now delegating to the shared module) confirmed
the refactor was behaviour-preserving before the fix (77/77, 0 orphaned/0
resolved) and reported the fix's effect afterward (31/31 dead, still 0
orphaned/0 resolved - the fix changed what counts as dead, not what this diff
did to it).

**Disposal of the 31 down to a fixed point:**

- DELETE (11, zero real consumer anywhere): `ping`, `installTool`,
  `pickSaveFile`, `pickOpenFile` (`ipc/client.ts`); `sanitizeMailHtml`,
  `prepareHtmlBody` (`lib/mailLinks.ts` - both `@deprecated`, superseded by
  `buildMailFrameDocument`, whose own tests already cover the same scenarios);

  that no other `.rs` file references `commands::ping`/`commands::install_tool`.
- Pruned the now-dead `formatLoadAvg`/`poolStateLabel`/`poolStateTone` test
