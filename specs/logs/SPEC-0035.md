## S2 — plan

Full plan: `/home/matheusmariano/.claude/plans/ticklish-mixing-kahan.md`
(approved). Summary:

**R1 decision:** an existing `orcker.toml` carrying `[php.pool]` loads with
the table **silently ignored** - not warned about, not migrated. Recorded in
`specs/DECISIONS.md` (2026-09-07 entry). Warning needs a doctor/CLI surface
and migrating implies a successor location for `max_children`; neither
exists and both are outside `crates/orcker-core/`/`crates/orcker-config/`.
Silently dropping a value nothing has read since SPEC-0002 removed the
native FPM pool manager is the only option available purely within surface.

**Cross-crate consumer check (why the surface holds):** grep across the
whole workspace found `php_pool`/its re-exports used only inside
`orcker-core` (definition) and `orcker-config` (`convert_pool`) - zero
references in `orcker-ipc`, `bin/orckerd`, or `bin/orcker`. The GUI's
`apps/orcker-gui/src/ipc/types.ts` has a `pool?: Record<...>` field that
*looks* related, but no Rust-side IPC code ever populates it - pre-existing
dead weight on the TypeScript side, unrelated to this spec's Rust surface,
left untouched.

**Mechanics that make AC1 non-trivial:** `PhpSectionWire` (parse.rs) carries
`#[serde(deny_unknown_fields)]`. Simply deleting its `pool` field would make
any pre-existing file with `[php.pool.*]` a hard parse error - the opposite
of "silently ignored". Kept the wire field, renamed `_pool: Option<toml::Value>`
via `#[serde(default, rename = "pool")]`: the leading `_` silences `dead_code`
with no `#[allow(...)]` (no clippy-allow-baseline touch beyond the one caused
by deleting `php_pool.rs` itself), and `toml::Value` accepts whatever shape is
there since nothing reads it again.

**Stale references caught by AC2's grep discipline:** `php_directives.rs`
had a dangling `[`crate::php_pool`]` intra-doc link and a hint string
claiming `pm.*` directives are "managed with `orcker php pool` (or the GUI
pool-size control)" - grepped `bin/` and `apps/orcker-gui` and found no such
command or control ever existed. Reworded to state the fact (not valid
ini-directive syntax) instead of pointing at a phantom feature.
