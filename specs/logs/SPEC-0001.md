### Decisions taken inside the plan

- `sonar-project.properties` is removed by R5; `.github/workflows/sonarqube.yml`
  exists only to consume it, so it goes in the same step. A workflow pointed at
  a deleted file is a broken CI job, not a neutral one.
- Workflows and docs that embed upstream URLs (`forjedio/yerd`, the Yerd CDN)
  are rewritten mechanically by P3 and will point at Orcker paths that do not
  exist yet. AC3 requires the brand to be gone, and repointing them at real
  infrastructure is a product decision outside this spec. Flagged, not fixed.
- Binary GUI icons (`icon.png`, `icon.icns`, `icon.ico`, the Square\*Logo and
  Android mipmap sets, the DMG backgrounds) carry no `yerd` string and stay in
  place; final visual assets are explicitly out of scope for this spec.

### The one test failure, and its root cause

`orcker_platform::pure::dns_probe::tests::query_encodes_probe_name_and_a_question`
failed with `left: 21, right: 19` at `dns_probe.rs:78`.

Root cause: `PROBE_LABEL` went from `yerd-resolver-probe` (19 bytes) to
`orcker-resolver-probe` (21 bytes). `compose_query` is length-driven
(`u8::try_from(label.len())`) and stayed correct; the *test* hard-codes the DNS
wire offsets, and every offset after the label shifted by 2.

Fix: the five offset literals in that test only — `19`→`21`, `13..32`→`13..34`,
`32`→`34`, `33..37`→`35..39`, `37..`→`39..`. No production code touched, no
assertion dropped or loosened: the test still pins the exact byte layout. Kept
as literals rather than deriving them from `PROBE_LABEL.len()`, because deriving
them would be a refactor and R8 allows only rename consequences.

`cargo test -p orcker-platform --lib` after the fix: `256 passed; 0 failed`.

### The second failure: R10 collides with a sentinel value

`orckerd::self_update::tests::current_version_parses` failed with
`left != right` where both sides were `0.0.0`, at `self_update.rs:491`.

Root cause: `current_version()` parses `env!("CARGO_PKG_VERSION")` and falls
back to `Version::new(0, 0, 0)` when the crate version is not valid semver. The
test guarded that fallback with `assert_ne!(current_version(), 0.0.0)`. R10
pins the real version at `0.0.0`, so the sentinel and the genuine value became
indistinguishable and the guard can no longer express its own intent.

Not a rename consequence: this one is caused by R10, and it would fire on any
project pinned at `0.0.0`.

Fix: assert the condition the sentinel stands for, instead of the sentinel.

```rust
let declared = semver::Version::parse(env!("CARGO_PKG_VERSION"));
assert!(declared.is_ok());
assert_eq!(current_version(), declared.unwrap());
```

Failing to parse is the only thing that fires the fallback, so this covers
exactly what the original covered, and it stays correct at any version. No
production code touched. The test module's existing
`#[allow(clippy::unwrap_used, clippy::expect_used, clippy::panic)]` at line 477
already covers the `unwrap`, so the step-5 baseline count for the file is
unchanged (`bin/orckerd/src/self_update.rs:1`).

`cargo test -p orckerd --lib` after the fix: `518 passed; 0 failed`.

Note on why this surfaced late: `cargo test --workspace` is fail-fast, so the
first run stopped at `orcker-platform` and never reached `orckerd`.

### Deviations for the supervisor

1. **AC3 cannot be satisfied as literally written.** It exempts only
   `docs/UPSTREAM.md`, `README.md` and `LICENSE.md`, but `rg -i yerd` also hits:
   - `CLAUDE.md` (3), `docs/PRD.md` (13), `docs/SDD.md` (6) and `specs/**` — these
     are the fork's own process and lineage documents, already written *for*
     Orcker, which reference Yerd on purpose ("forked from Yerd", "replaces
     Yerd's native runtime"). Substituting there turns SPEC-0001's own title
     into "Rebrand the Orcker fork".
   - `apps/orcker-gui/package-lock.json` and `docs/package-lock.json`, one line
     each: the substring `YerD` inside the npm integrity hash
     `sha512-NxnomyxYerDh5n4iLrNa+...`. Case-insensitive only, and unfixable —
     editing it would corrupt the lockfile.

   Proposed AC3, unchanged in intent: add
   `-g '!CLAUDE.md' -g '!docs/PRD.md' -g '!docs/SDD.md' -g '!specs/**' -g '!**/package-lock.json'`.
   Under that glob set the command returns no matches. The product surface —
   `crates/`, `bin/`, `apps/`, `xtask/`, `scripts/`, `packaging/`, `.github/`
   and the docs site — is clean.
2. **`.github/workflows/sonarqube.yml` removed** alongside the
   `sonar-project.properties` that R5 names. It consumes only that file; leaving
   it would be a permanently red CI job.
3. **Upstream URLs rewritten mechanically.** `forjedio/yerd` and the Yerd CDN
   hosts in `build-cdn.yml`, `cdn-sync.yml`, `release.yml` and the docs now read
   as Orcker paths that do not exist. AC3 forces the rename; repointing them at
   real infrastructure is a product decision outside this spec.
4. **Binary GUI icons left in place.** `icon.png`, `icon.icns`, `icon.ico`, the
   `Square*Logo.png` set, the Android `mipmap-*` set, `StoreLogo.png` and the two
   DMG backgrounds are still Yerd's rendered "Y" mark. They carry no `yerd`
   string, and SPEC-0001 puts new visual assets out of scope. Filed as
   `specs/SPEC-0029-replace-binary-brand-icons.md` (`draft`), queued in
   `specs/ROADMAP.md`.
