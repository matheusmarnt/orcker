## S1 — context

SPEC-0038 was the first `approved` spec in `specs/ROADMAP.md` order whose
`depends_on` (SPEC-0002, SPEC-0036) is `accepted` - confirmed against `HEAD`,
not the ROADMAP status column, via `git show "HEAD:$spec" | awk -F': '
'/^status:/{print $2; exit}'`. Branch `feat/SPEC-0038-tauri-host-coverage`.

Read the spec, `CLAUDE.md`, `.github/instructions/orcker-gui-{backend,frontend}.instructions.md`,
and the files in `surface` (`apps/orcker-gui/`).

**Findings that shaped the plan** (verified this session, three parallel Explore
agents plus direct greps):

- Two spec premises were stale. `src-tauri/` is not untested: six
  `#[cfg(test)]` modules exist (`commands.rs` 14 tests, `tray.rs` 8, plus
  `autostart.rs`/`daemon.rs`/`logging.rs`/two macOS-gated modules) and
  `cargo test -p orcker-gui` already ran 48 tests at `HEAD` - but none of them
  ever executed `on_menu_event`, `NAV_ITEMS`, badge derivation, or a command's
  decision logic, so AC2 as originally written was already satisfied
  (tautology risk, DT4/JG5). R4's `main.rs`/`WebviewUrl::App` clause referenced
  code that does not exist (zero `WebviewUrl` occurrences, grep-verified) -
  windows are declared statically in `tauri.conf.json` and fetched by label.
  Corrected in its own commit before any test, per the SPEC-0039 precedent
  (`e19c72f` then `65f5d45`).
- `tray.rs`'s 8 existing tests are icon-pixel/serde only
  (`menu_icon_*`/`recolor_opaque_*`/`y_glyph_rgba_*`/wire-name serde); none
  touch the dispatcher.
- `apps/orcker-gui/src-tauri` is a workspace member with no `[lib]` target
  (bin-only crate, `main.rs` calls `fn main()` directly) - tests must live in
  `#[cfg(test)] mod` blocks against `super::*`/private items, never a `tests/`
  integration dir.
- `ipc.rs::exchange_at` already advertises its own test seam ("Factored out so
  tests can target a tempdir socket") but nothing used it; it does a plain
  `write_message`/`read_message` round trip with no version-skew handshake
  (out of scope - see S6).
- `routeTargets.test.ts`'s tray half scans `tray.rs` text for `"nav:(/x)"` and
  `emit("navigate", "/x")` literals; the second pattern already stops matching
  once a payload is a variable, and after R1 both `update:apply` and the
  `nav:` fallback pass a route through a variable rather than a literal.
- The `sites-intent` contract spans four places with nothing checking them
  against each other: `tray.rs` emits `"link"`/`"park"`, `App.vue`'s listener
  hand-checks the same two literals, `SitesView.consumeIntent` branches on
  them, and `sitesIntent.ts` names the `SitesIntent` union - exactly the shape
  of SPEC-0036's REWORK (a tray item emitting an intent nothing consumed).

## S2 — plan

Approved plan (`/home/matheusmariano/.claude/plans/enumerated-yawning-sifakis.md`):

- **R1** - extract `tray.rs`'s decisions into a pure `MenuAction<'a>` enum +
  `menu_action(id: &str) -> MenuAction<'_>`, and `badges_for(&TrayState) ->
  Badges`; `on_menu_event`/`apply` become thin callers. Separate `MenuAction`
  variants (not a `(bool, topic, payload)` triple) so each effect arm keeps its
  topic string written once, exactly as today.
- **R2** - extract `commands.rs`'s `staged_kind_str(StagedArtifact) ->
  Option<&'static str>` from `apply_update`'s inline match; test it and
  `parse_channel` (already pure, untested). Add a faked-daemon round-trip test
  in `ipc.rs` exercising `exchange_at` directly (a tempdir Unix socket, no
  handshake needed), since command handlers have no injectable IPC seam to
  fake through.
- **R3/R4** - narrow `routeTargets.test.ts`'s tray scan to the `nav:` pattern
  only (the `emit("navigate", ...)` pattern is now provably redundant once the
  dispatcher has behavioural tests), add a non-zero-count guard against a
  silent stop-matching, and add a `tauriConfTargets()` scan of every
  `app.windows[*].url` against the router.
- **R5** - a pure `tests/sitesIntent.mjs` (extractor functions over source
  text, no fs/git) plus `tests/sitesIntent.test.ts` (fixture unit tests +
  a real-tree equality check across all four sources), matching the
  established `contractMirror.mjs`/`deadExports.mjs` shape.
