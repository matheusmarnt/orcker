## S2 — plan

`error::tests::display_validate_each_variant_non_empty` iterated a hand-written
array literal of `ValidateErrorReason` values. An array literal type-checks fine
even when it omits variants (as it did: `RouteRuleDuplicatePrefix` and
`RouteRuleUnknownSite` were never added when SPEC-0053 introduced them), so the
test can never catch the next omission — exactly the gap R1 names.

No new dependency (`strum`/`enum-iterator` are not in `[workspace.dependencies]`
and this is a 38-variant `Copy` enum with a single call site — not worth one).
The fix stays inside `#[cfg(test)] mod tests`: a free function
`every_validate_error_reason()` builds the list by walking a `match current { ...
}` from the first variant to the last, one arm per variant, no wildcard. Rust's
exhaustiveness check (`E0004`) then fires the moment a variant is added without
a matching arm, and fires again (as an unresolved-path `E0599`) if an arm still
names a variant that was removed — both directions of "the enumeration goes
stale" become compile errors instead of a silently narrower runtime list.
`display_validate_each_variant_non_empty` calls this function instead of the
literal array; no other test touches `ValidateErrorReason`.

## S3 — RED evidence

Built `every_validate_error_reason()` first with the LHS arms for

exact gap in the array it replaces), then ran:

```

```

Result: **compile failure**, not a test failure — proving the mechanism itself,
before it even runs a test body:

```

   --> crates/orcker-config/src/error.rs:324:29

```

This is the AC1 property demonstrated directly: the same two variants the old
array silently dropped are the two the compiler now refuses to build without.
