## S2 — plan

Full plan: `/home/matheusmariano/.claude/plans/replicated-chasing-clock.md`
(approved). Summary:

**R1 decision:** Hello/Welcome handshake exchanging `PROTOCOL_VERSION` on
connect - not the `#[serde(other)]` fallback alternative. This is not really
a free choice: `orcker-ipc/src/lib.rs`'s module doc and `response.rs`'s
`ErrorCode` doc both already name "a Hello/Welcome handshake" as the intended
fix (written by SPEC-0002's author), and
`.github/instructions/orcker-ipc.instructions.md` commits the crate to
"a handshake before the first incompatible change". A bare fallback variant
would make an unknown request decode, but the daemon still couldn't name
*which* versions disagree without something carrying `PROTOCOL_VERSION` on
the wire.

**Two complementary, both-necessary pieces** (an optional handshake alone
would not satisfy AC1, because `apps/orcker-gui` is outside `surface:` and
has its own independent `exchange_at` that will never send `Hello`):

1. New `Request::Hello{version}` / `Response::Welcome{version}` /
   `ErrorCode::VersionMismatch` (additive wire types). `bin/orcker/src/transport.rs::exchange_at`
   sends `Hello` before the real request; a `Welcome` reply proceeds exactly
   as before, anything else is returned immediately without ever sending the
   real request (reusing the CLI's existing `Ok(Response::Error{message,..})`
   handling at every call site - confirmed by grep, no `ClientError` variant
   or call-site changes needed).
2. `bin/orckerd/src/ipc_server.rs::handle_client`: a `Request::Hello` reply
   compares versions; and, separately, any `IpcError::Decode` while reading
   (today: logged and the connection silently dropped) now writes
   `Response::Error{code: VersionMismatch, ..}` and keeps the connection
   alive - this is what protects the GUI too, unconditionally, with zero
   GUI-side changes.

## S4 — implement

Smallest diff that turns S3 GREEN, one AC at a time:

- `crates/orcker-ipc/src/request.rs`: `Request::Hello { version: u32 }`,
  appended to the enum + `pin`/`touch_every_variant`.
- `crates/orcker-ipc/src/response.rs`: `Response::Welcome { version: u32 }`
  and `ErrorCode::VersionMismatch`, appended + `pin_response`/`pin_code`/
  `touch_every_variant`; rewrote the `ErrorCode` doc note that named the
  handshake as a future fix (it now exists).
- `crates/orcker-ipc/src/lib.rs`: module doc + `PROTOCOL_VERSION` doc comment
  rewritten (AC3) - no longer says the constant is informational or never
  travels on the wire.
- `bin/orckerd/src/ipc_server.rs::handle_client`: a `Request::Hello` arm
  (compares `version` against `PROTOCOL_VERSION`, replies `Welcome` or a
  typed `VersionMismatch` error); and the `Err(e)` branch of the
  `read_message` match now splits out `IpcError::Decode(_)` to reply
  `Response::Error{code: VersionMismatch, ..}` and `continue` the loop
  (frame boundary is intact - only the JSON `type` tag was unrecognized -
  so the connection stays usable) instead of silently `return`ing. Every
  other error kind keeps the prior silent-close behavior.
- `bin/orcker/src/transport.rs::exchange_at`: sends `Request::Hello` before
  `req`; a `Welcome` reply proceeds exactly as before; anything else is
  returned immediately as the exchange's result, without ever sending `req`.
  No `ClientError` variant added - reuses the `Ok(Response::Error{message,..})`
  handling every CLI call site already has.
- New test file `bin/orcker/tests/transport_handshake.rs` (see S3).

`apps/orcker-gui` (outside `surface:`) was not touched, by design - see the
plan's design note. It is protected by the daemon-side decode-error fix
alone, not the proactive preflight.
